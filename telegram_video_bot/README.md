# Telegram-бот для сповіщень про нові відео

Бот на Python та aiogram 3 перевіряє відкриті профілі TikTok через `yt-dlp`
і надсилає адміністраторам прев'ю та посилання на нові відео. Самі відеофайли
не завантажуються. Профілі та історія відео зберігаються у Supabase.

## Налаштування

1. Створіть бота через [@BotFather](https://t.me/BotFather) і скопіюйте токен.
2. У Supabase відкрийте **SQL Editor**, виконайте вміст
   `telegram_video_bot/supabase_schema.sql`.
3. У Railway відкрийте **Variables** сервісу та задайте:

   - `BOT_TOKEN` — токен Telegram-бота.
   - `ADMIN_IDS` — числові Telegram user ID адміністраторів через кому.
   - `SUPABASE_URL` — Project URL із налаштувань Supabase API.
   - `SUPABASE_SERVICE_ROLE_KEY` — service-role key із налаштувань Supabase API.

   Service-role key надає повний доступ до бази: зберігайте його лише в
   Railway Variables або іншому серверному сховищі секретів. Не додавайте його
   до Git, клієнтського коду чи повідомлень.

4. Кожен адміністратор має відкрити бота в Telegram і надіслати `/start`,
   інакше Telegram не дозволить боту написати йому приватно.
5. Для локального запуску задайте ті самі значення як змінні середовища
   процесу, встановіть залежності та запустіть із кореня репозиторію:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install --upgrade pip
   pip install -r telegram_video_bot/requirements.txt
   python -m telegram_video_bot.main
   ```

Бот читає лише змінні середовища процесу й перевіряє доступ до Supabase під час
запуску. Він не завантажує налаштування з `.env`; у Railway використовуйте
**Variables**, а локально — середовище PowerShell або середовище запуску IDE.
Для перевірки доступності Railway-сервіс слухає порт `PORT` і повертає `ok` за
адресами `/` та `/health`. Це підтверджує роботу HTTP-процесу, але не доступність
Telegram чи Supabase і не обходить ліміти тарифу Railway.

## Команди в Telegram

- `/start` і `/menu` — головне inline-меню з кнопками керування.
- `/chatid` — показує ID користувача й поточного чату.
- `/profiles` — список профілів TikTok з ID.
- `/add_profile https://www.tiktok.com/@handle` — додати профіль.
- `/remove_profile 1` — видалити профіль і його історію.

Команди керування доступні лише ID з `ADMIN_IDS`. Сповіщення надсилаються
приватно всім адміністраторам; окремий `TELEGRAM_CHAT_ID` не потрібен.
Кнопки меню перемикають розділи в одному повідомленні, тож панель залишається
під рукою; команду `/menu` також можна відкрити з меню команд Telegram.

Під час додавання профілю його наявні відео записуються як початкова історія,
тому сповіщення починаються з наступних публікацій. Якщо профіль уже існує,
повторне додавання не створює дублікат.

## Налаштування моніторингу

- `POLL_INTERVAL_SECONDS` — інтервал перевірки; мінімум 60 секунд, типовий —
  900 секунд.
- `MAX_VIDEOS_PER_PROFILE` — скільки останніх відео читати за цикл (1–50,
  типовий — 20).

Схема Supabase має бути створена до запуску. Дані з попередньої локальної
SQLite-бази автоматично не переносяться.

TikTok іноді блокує або змінює доступ до публічних метаданих. У такому разі
бот запише помилку в лог і повторить перевірку під час наступного циклу. Він
не обходить приватність профілів чи обмеження доступу.
